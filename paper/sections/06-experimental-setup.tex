\section{Experimental setup}

\paragraph{Reference baselines.}
We run four programmatic baselines on each test split (\texttt{run-baselines}): \textbf{oracle} emits gold MIDI and plan; \textbf{copy\_source} returns the unchanged input; \textbf{wrong\_transform} executes the correct operator family with deliberately incorrect parameters; and \textbf{no\_output} represents total generation failure. These controls test the expected metric boundaries rather than serve as competitive systems. Table~\ref{tab:overall-results} reports them on v0.2 real MIDI; Table~\ref{tab:control-results} repeats the check on the synthetic pilot.

\paragraph{Plan-then-execute baseline.}
We evaluate \texttt{meta-llama/Llama-3.2-1B-Instruct}~\cite{dubey2024llama3} as an open, lightweight instruction-following baseline. The model receives the natural-language edit instruction, allowed operation schema, and a summary of available MIDI tracks, then greedily generates a JSON plan with temperature~0. On the pilot we cap generation at 128 tokens; on v0.2 we use a 256-token cap after observing frequent truncation at 128 on longer real files. A deterministic executor validates the plan and applies the requested operation using \texttt{pretty\_midi}; malformed plans or execution errors receive no MIDI output and are retained as failed predictions. Inference uses half precision on a single NVIDIA T4. No examples from the train split, fine-tuning, retries, or output repair are used.

\paragraph{Prediction format.}
Models write one MIDI file per item. JSONL predictions reference \texttt{midi\_path} relative to the predictions file and optional \texttt{plan}.

\paragraph{Reporting.}
We report mean \edit{}, \preserve{}, joint pass rate, OverEdit, and gold note-F1 overall and by \texttt{op\_family}. Plan match is reported separately as MIDI-Reason. Validity counts whether the runner emits a parseable MIDI; prediction coverage counts submitted JSONL records and is 100\% because failed attempts remain explicit records. For v0.2 we additionally report \textbf{composition\_macro} aggregates (equal weight per composition). Headline model numbers use the v0.2 test split: 180 items from 45 compositions.

\paragraph{Grader validation.}
Before publishing model numbers, run \texttt{self-test} on the released manifest. Any joint $< 1$ indicates predicate or transform bugs, not model failure. \texttt{stress-test} applies transpose and tempo transforms to external MIDIs (local directories or MidiCaps/Lakh paths) and self-scores gold vs.\ gold to catch parser edge cases on real files.

\paragraph{Reproducibility.}
The evaluation harness writes all prediction records, generated MIDI files, aggregate reports, and per-item predicate details; these files must be kept together because prediction paths are relative. The same CLI commands regenerate programmatic baselines and rescore model outputs. We archive the complete result bundle with the paper release rather than relying on machine-specific paths in intermediate reports. Constraint-gold descriptive items, licensed seed corpora, multi-step instructions, tool-augmented agents, and self-refinement can reuse the schema with additional runners.
