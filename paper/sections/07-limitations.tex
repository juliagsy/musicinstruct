\section{Limitations}

\begin{itemize}[leftmargin=*]
\item \textbf{Seed diversity.} v0.1 items are fully synthetic; v0.2 draws from filtered MidiCaps/Lakh MIDI but still uses deterministic unique gold. Absolute scores may not transfer to professional arrangements or longer multi-section works.
\item \textbf{Correlated test items.} v0.2 test subsampling caps items per composition, yet four edits still share one source file. We report composition-macro aggregates alongside item micro-averages; neither replaces evaluation on entirely held-out musical styles.
\item \textbf{Unique gold only.} Descriptive instructions with many valid outputs are deferred; current metrics may over-penalize creative but valid edits once constraint gold arrives.
\item \textbf{Predicate scope.} \preserve{} evaluates each item's declared predicate list, not every possible MIDI event or metadata field. In particular, within-mask attributes not named by a predicate may change without reducing \preserve{}. Broader releases should add operation-specific invariants and adversarial tests.
\item \textbf{Operator coverage.} Five programmatically verifiable families do not cover harmonization, re-orchestration, or bar-level rewriting; difficulty is intentionally controlled for grader validation. The v0.2 test split in this release omits velocity scaling after subsampling.
\item \textbf{Single model baseline.} The model study uses one small open LLM with greedy decoding and no retries. It establishes that the harness exposes interpretable failures, not a ranking of current instruction-following systems.
\item \textbf{Plan representation.} Exact plan match can reject a plan that produces a predicate-correct file when parameters differ from the canonical representation. We therefore treat plan match as diagnostic and file-level joint success as primary.
\item \textbf{Generation cap.} Many v0.2 failures are incomplete plans under a 256-token cap, often from over-long track lists. A larger cap, constrained decoding, or schema repair would likely improve validity, so the reported score characterizes this fixed runner rather than the model in isolation.
\item \textbf{Tempo estimation.} BPM ratio checks depend on pretty\_midi tempo estimation; extreme rubato seeds may add noise. On v0.2, the oracle baseline reaches joint 0.933 rather than 1.0, indicating remaining grader--gold mismatches on real MIDI that \texttt{self-test} and \texttt{stress-test} should drive toward closure.
\end{itemize}
